# Conductor Addendum — Algebra Engine Beta v1

Place this file in the project root beside `START_HERE.md`. Read it after
`CLAUDE_CODE_START_PROMPT.md` and before writing code.

## 0. Authority

This addendum overrides the handoff package only on the points it names.
Everything it does not name is governed by the package as written. If this
addendum conflicts with a mathematical fact or with one of the 15 invariants in
`CLAUDE.md`, stop and report the conflict. Do not resolve it silently.

The product owner's decisions in section 2 are final for this beta. Do not
reopen them.

## 1. Build log and timing

Before any other action, create `BUILD_LOG.md` and record the UTC start time of
this session. Record the UTC time each gate test run passes or fails. Record

## 2. Owner decisions

**D1 — Socratic repair.** During GUIDED_REPAIR the tutor teaches only through
questions. Each learner-facing message asks for one action. When the learner
is stuck (incorrect step, REQUEST_HINT, or "I don't know"), the tutor breaks
the current step into a smaller question. It never presents a worked example,
a complete solution, or the final answer to the active item. Feedback may state
what the learner's answer did ("Your answer multiplied only the x by 3"), then
ask the next question.

**D2 — Targeted descent.** When a breakdown is confirmed, descend one
prerequisite edge at a time along the branch the observed error implicates.
Keep stepping down until the learner succeeds independently or the beta
boundary is reached. Do not drop a fixed number of levels. Rationale: the
curriculum is a branching graph (Q07 depends on both Q06 and E06); a fixed
level count does not identify which branch to follow.

**D3 — Q07 can complete in the beta.** Implement Q07's three required variants
with deterministic checking so Q07 can reach IMMEDIATE_CRITERION_MET (section 5).

## 4. Package defect fixes

**F1 — Manifest.** Run `sha256sum -c MANIFEST.sha256` before running
`tools/validate_handoff.py`. The preflight rewrites
`HANDOFF_PREFLIGHT_REPORT.json`, so a mismatch on that one file afterwards is
expected. Any other mismatch is a real failure; stop and report it.

**F2 — No example content in prompts.** The owner's architecture forbids
example responses in prompts.
- Do not include `examples/model-question.json` in any prompt. Replace the
  "Example shape" line in the prompt assembly with a skeleton generated from
  `contracts/model-envelope.schema.json`: every field present, values are type
  placeholders only (`"<string>"`, `"<integer>"`, `null`). No mathematical
  content, no learner text.
- Strip `assessment.anchor_item` from every skill record injected into a
  prompt. Anchors remain available to tests and the ItemFactory only.
- Add a test that assembles a prompt and fails if it contains any anchor
  prompt string or any string from `examples/`.

## 5. Beta scope

### In

**Skills.** Q07 (target), Q06, Q05, Q04, E06, N18, N03, N04, N05, N06.
Edges come only from `curriculum/algebra-map.json`. Implement an ItemFactory
template for each; add `WHOLE_MULTIPLY_DIVIDE` for N18 (whole numbers, 2..12
factors, exact quotients).

**Beta boundary.** Q03, A07, N02, N17 and every other skill are outside the
beta. If descent reaches one, record "not available in beta", report the
unresolved branch, and do not label the learner as failing that skill.

**Q07 variants (D3).** Each checked deterministically in PHP:
1. Constructed: `GROUPED_LINEAR`, scalar answer, exact rational.
2. Contrast: a classification item. Given `a(x+b)=c`, the learner selects
   every valid first step from four options generated by the host (for
   example: divide both sides by a; distribute a to both terms; subtract b
   from both sides; multiply only x by a). The host derives the key. Order
   of options is randomized per item.
3. Transfer: `a(x+b)+d=c` or `c=a(x+b)`, scalar, exact rational.

Q07 IMMEDIATE_CRITERION_MET requires three consecutive independent correct
accepted items that together include all three variants. Apply the same
three-variant rule to E06 (constructed expansion; contrast on whether the
factor reaches every term; transfer to a fresh structure). The other beta
skills use the package's numeric-component rule and report PARTIAL_COMPONENTS
where their full node requirements are not implemented.

**Error signatures.** For `GROUPED_LINEAR`, the host computes the answers
produced by known error patterns: distributing to x only; sign error on b;
dividing c by a then adding b; arithmetic error in the final step. A response
matching a signature is recorded as an observation ("matches
distribution-to-x-only"), never as a confirmed cause. The signature selects the
branch for the diagnostic probe and for descent (distribution signature → E06;
inverse-operation or arithmetic signature → Q06 branch).

**Slip check.** After an incorrect Q07, give one fresh diagnostic probe that
varies the implicated component. Correct → record "error not reproduced", no
descent, resume target assessment (the streak stays broken). Incorrect →
descend per D2.

**Entry route.** One route: the learner picks a skill from the beta list.
Default target is Q07.

**Host and safety.** Mock provider and real provider adapter (configurable
OpenAI-compatible endpoint; mock is default); binding call then JSON envelope
calls; envelope schema validation; host key derivation and checking; SQLite
storage; session cookie ownership; CSRF; revision and idempotency checks; no
answer keys or envelopes in any public payload; session report; forget; mobile
and desktop UI; English only.

**Answer-disclosure guard (D1).** In GUIDED_REPAIR, reject a model message that
contains the active item's expected answer as a standalone token, and request
one bounded repair. This guard is a heuristic; record it as such in the
capability matrix.

### Deferred (list in the capability matrix as not implemented)

Teacher task links; "help me find a starting point" orientation; free-text
topic mapping; resume across sessions; review and retention checks; transfer
checks outside Q07 and E06; graph, table and reasoning-rubric inputs; all
skills outside the beta list; localisation; accounts.

## 7. Report

The session report lists, per skill touched: items attempted, independent
versus assisted, verdicts with checking scope, error signatures observed (as
observations), descent path, and criterion status. It never says "mastered".
It labels mock-provider sessions as mock.

## 8. Beta Gate

The beta is done when all of the following are true and recorded in
`BUILD_LOG.md`:

1. Every test in section 6 passes, with output saved to `test-results/`.
2. B1 runs end to end in a browser at mobile and desktop widths, in mock mode.
3. The capability matrix lists every beta skill with its implemented variants
   and checkers, and every deferred item.
4. A Bluehost public/private upload ZIP and deployment instructions exist.
   Do not deploy.
5. A live provider smoke test has run if a key was supplied; otherwise the
   matrix states it has not run.
