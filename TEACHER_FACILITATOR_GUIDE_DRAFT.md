# Facilitator guide — draft for the future application

This describes intended use after implementation. It is not a report of a
working application or an observed learner session.

## Before a session

Choose a relevant target from the curriculum. If the learner has a current
classroom problem, use it to identify that target. Check the app's capability
label: an available numeric component may not cover a complete modeling,
explanation or graph-construction skill. Do not substitute it for the missing
component in a classroom assessment.

Use Prepare a task to select a target and optional public instructions. The
account-free task link contains no student records, does not lock settings and
does not give its creator report access. For this initial version, sit with
the student or ask them to show/export the report. A private class dashboard
and authenticated teacher scoring are later features.

## During a session

Ask the learner to enter their own answers and use the working field when
helpful. If an adult supplies a method or answer outside the app, record that
support before treating the result as independent. The initial product cannot
detect unreported adult help. Hints inside the app are recorded automatically.

Let the engine investigate a wrong answer before explaining the entire
solution. A short prerequisite detour should return to the original target.
If it does not, the session is incomplete and that return still needs testing.
The learner can stop, skip, say they have not learned something, or change topic.
Those actions are not mathematical failures.

## Reading the summary

Look for the actual independent work, assistance, scoped repair and fresh
return-to-target results. Separate an immediate criterion from transfer and
later retention. Untested curriculum skills remain untested. A model's
interpretation of an explanation is not deterministic proof of understanding.
An unsupported graph task describes an app limitation, not a learner deficit.

## Pilot observations to collect

Record whether the starting recommendation was useful, whether the question
was clear, whether a correct response was rejected or an incorrect one accepted,
whether a hint helped, whether the prerequisite route was relevant, and whether
the learner could independently return to the original task. Record exact
examples before changing policy. Avoid collecting names or unnecessary details.

Later independent work can supply retention evidence only when it is actually
collected with timing/provenance. A second immediate question is not delayed
retention. Report learning outcomes only after real learner testing.
