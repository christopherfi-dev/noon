# 07 — Build sequence and release gates

## Stage A — Wiring and first complete journey

1. Run the package preflight; verify curriculum counts/IDs and environment.
2. Build app/public and private PHP modules with mock mode, storage migrations,
   trusted events, revisions, idempotency and a public projection.
3. Implement all three entry routes, orientation seeds/recommendation and public
   teacher task setup. No accounts or historical student data are required.
4. Implement safe numeric/polynomial parsers, server-owned first item families,
   correct/incorrect/ambiguous distinctions, hint provenance and state guards.
5. Make Q07 → diagnostic probe → E06 repair → independent check → fresh Q07
   return run end to end. Preserve a deeper prerequisite return stack if needed.
6. Build honest component-level progress and session reporting. Add actual
   required reasoning/representation criteria before promoting the whole node.
7. Add the real provider adapter, binding and envelope validation. Mock answers
   exercise the same host acceptance pipeline as real output.

Gate A: tests prove the first journey, all entry routes, support tracking,
topic switching, context replacement, correction and transaction safety.
Run a local browser walkthrough at mobile and desktop widths. Record unavailable
live-provider tests if no key exists. This is a demonstrable first implementation,
not the entire curriculum operationally covered.

## Stage B — Full core coverage

Expand factories, parsers, graph/table inputs and required rubric routes across
all 148 core skills and on-demand foundations. Per-skill coverage maps every
required variant/response/checker to implemented tests or explicit gaps. Do not
hide graph/modeling/reasoning omissions behind a green skill status.
Preserve canonical IDs and the 205-node map. Optional extensions are opt-in and
cannot become compulsory core gates. Complete deterministic coverage where
possible and expose REVIEW_REQUIRED for genuinely unimplemented review routes.

Gate B: all advertised scored skills meet their complete declared requirements.
Any remaining core gap is listed, not described as full core completion. If
authenticated human review is necessary, it is a separate approved feature,
not a hidden public 'teacher' toggle. Continue available implementation work
without inventing this identity feature.

## Stage C — Pilot and learning evidence

Teacher mathematical/semantic review, observed student usability, diagnostic
route testing and revision. Record what the learner actually does and how
often routing/feedback fails. No learning-gain claim from mock or application
unit tests. Durable mastery needs actual later evidence.

## Required application tests

Implement contracts/acceptance-scenarios.json as integration/state tests plus
browser tests where relevant. Mathematical fixtures are golden expected
outcomes, not a complete operational checker. Add metamorphic/property tests
for real parser/equivalence/solution routines (e.g. signs, fractions, roots,
domain exclusions and overflow), not just copies of implementation logic.

Test mock timeouts, malformed JSON, repeated requests, stale revision, support
before commit, forged promotion, unsupported tasks, missing resources, context
replacement and late provider results. A live smoke test confirms network and
adapter compatibility only, not instructional validity.

## Definition of the implementation handoff result

Claude Code supplies working local app code; tested run commands; test results
with failures/untested scope; browser findings; per-skill capability matrix;
Bluehost public/private upload ZIP; deployment and rollback instructions;
remaining work. Missing secrets are configured privately, never committed.
Nothing is deployed until the owner requests deployment.

## Noon portfolio evidence after the app runs

Record a short actual learner-path walkthrough, show curriculum/assessment
design, show a verified rejected bad answer/item, explain a revision from
observed use, and include a facilitator guide. Describe these as built/tested
only when they exist. The curriculum package alone is not evidence of a live
high-school tutor or measured learning improvement.
