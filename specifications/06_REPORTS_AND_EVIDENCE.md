# 06 — Reports, provenance and evidence claims

The report is generated from accepted ledger events, with optional model
wording checked against that data. In v1 it belongs only to the owning browser
session, with print/export. Public task creators cannot retrieve it remotely.

Required report sections: targets attempted; independent correct, incorrect
and partial observations; guided work; repair points and return outcomes;
immediate criterion by component/skill; transfer actually tested; later review
actually observed; interruptions, untested requirements and system limits;
next evidence needed. Each factual learning claim lists relevant event/item
IDs and review scope. Keep author-designed routing recommendations separate
from measured outcomes.

Hypotheses use UNRESOLVED, PROVISIONAL, SUPPORTED_FOR_OBSERVED_PATTERN or
CONTRADICTED, with supporting/contradicting events. No permanent learner traits.
One correct probe means an error was not reproduced, not a confirmed slip.
Do not infer every prerequisite is missing or classify all 205 nodes.

Example permitted: 'On two distribution tasks, the factor was applied only to
the variable term. After guided work, the learner correctly expanded three
fresh expressions without hints. A fresh original-target equation still needs
checking.' Impermissible: 'The student had a distribution misconception and
has now mastered equations.' Whole-node claims require all declared components.

Counters must distinguish the immediate default policy, meaningful transfer,
and timestamped later retention. Include architecture/curriculum/policy versions,
session timing, completed/interrupted status, checker provenance and limitations.
Never render internal issue names in ordinary student feedback. Technical
exports may include scoped system issues, never secrets or chain-of-thought.

No dashboard, teacher inbox or classroom analytics is in account-free v1.
If such features are later requested, add real identity/authorization and data
boundaries before exposing cross-session reports.
