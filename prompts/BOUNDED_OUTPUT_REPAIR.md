# Bounded repair request template

The host rejected the previous proposal. This is a private control message.
It is not a new learner answer, a learner failure or an accepted state change.

Provide: failed attempt ID; unchanged trusted state/revision/event; exact
schema or acceptance error paths; bounded allowed corrections; remaining
attempt budget; actual checker capabilities. Do not repeat secrets or expose
keys. Ask for one corrected JSON envelope. Do not invite changes to an accepted
verdict, canonical skill definition or identity. After two unsuccessful output
repairs, hold the affected operation, preserve work and explain the limitation
in ordinary learner language. Never loop indefinitely to obtain a pass.
